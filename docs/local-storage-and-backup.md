# 內建 Storage 與備援設計（OnePage C61）

狀態：**已與 Kevin 確認方向**，待基線韌體建置驗證後實作。

## 目標
1. **沒有 microSD 也能用**：改用內建 flash 當儲存。
2. **插入 SD 時**：把內建儲存複製到 SD（單向）。
3. **備援要保險**：任何單一故障（斷電、SD 壞、裝置遺失）都不丟不可重建的資料。

## 資料分類（備援重點）
| 類別 | 例子 | 來源 | 備援需求 |
|---|---|---|---|
| 可重建 | 電子書、封面 | readflix | 低（重抓即可） |
| **不可重建** | 閱讀進度、書籤、設定、使用者上傳的圖片/識別證 | 裝置本身 | **高** |

## 四層備援
1. **韌體可回復**：原始 16MB flash 備份（private repo）＋ 官方 Web Flasher；自製 `.bin` 亦存 repo；保留 `app1` 做 OTA A/B 回滾。
2. **原子寫入**：所有檔案 `寫 temp → flush → rename` 覆蓋；停電不得產生半檔。內建後端必須遵守同一契約。
3. **搬遷協定（內建→SD）**：
   - 只複製、**不刪除來源**；逐一驗證（大小＋檢查碼）通過才標記「已同步」。
   - 同步中斷電 → 下次開機依「同步中」旗標整段重做（冪等）。
   - SD 讀不到/壞掉 → 不動內建，落回內建並提示。
4. **離機備援（最強）**：透過 Tailscale 定時把不可重建的小資料（進度、書籤、設定、**圖片**）上傳到伺服器（readflix 小 API 或自建端點）。

## 開機決策（單向、可預期）
```
開機
 ├─ 有 SD？
 │   ├─ 有 → SD 為主
 │   │        └─ 內建有「未同步」→ 先複製內建→SD（只補/覆蓋內建有的檔）→ 驗證 → 清旗標
 │   └─ 沒 → 內建為主
 │            └─ 任何寫入 → 標記「內建未同步」
```
- 有卡期間的變動不回寫內建（單向，避免雙向同步的災難）。
- 同步成功後內建**保留當鏡像**（不清空）→ 隨時有第二份。
- 卡上既有內容：以卡為準，內建只補它沒有的。

## 技術實作
- **單一介入點**：`HalStorage` / `HalFile`（上層閱讀器/圖片/網路皆不動）。
- 在 `SDCardManager` 加**第二個 SdFat volume**，掛在 flash 分區（現有 `spiffs` 3.4MB；不足時重切分區）。
- 新增一個 `BlockDevice`（實作 SdFat `BlockDevice`）把 sector 讀寫映射到 ESP-IDF 分區：
  - `readSector` → `esp_partition_read`
  - `writeSector` → 讀-改-寫 4KB 擦除塊（`esp_partition_erase_range` + `write`），帶 block cache
  - 首次使用若無 FAT → `FatFormatter::format()`
- `begin()`：先試 SD → 失敗則掛內建；`vol()` 回傳當前 volume。
- 需為 onepage env 加上 `-DUSE_BLOCK_DEVICE_INTERFACE=1`。

## 已知取捨
- 內建採「SdFat FAT 直掛 flash」：改動最小、上層零修改，但**無磨損平均**；高頻小檔（閱讀進度）以延遲/合併寫入降低擦寫。
- 容量：起步 3.4MB，需要再重切分區（app 目前用不到 6.4MB）。
- 開機韌性：內建 FS 掛載失敗仍須能開機並提示，不可變磚。

## 里程碑
1. 基線：`pio run -e onepage` 成功、燒錄、開機驗證。
2. 內建 storage fallback（無卡可開機、可讀寫）。
3. 搬遷協定（內建→SD，驗證後標記）。
4. 伺服器備援（Tailscale + 小同步端點）。
